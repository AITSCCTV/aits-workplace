# Content Studio AI Instructions

Marketing users with the Content Studio tool grant and signed-in administrators can open **AI Instructions** in the library. The four fields control research, Monday education, Thursday marketing, and caption/SEO style. Save applies to future runs; it never generates or publishes a post. Preview is text-only. Restore loads an older version into the editor and requires Save to activate.

The authenticated Workspace endpoint is `/project-board/api/staff/admin/content-studio/instructions` (GET/PUT). Versions are append-only in `content_studio_instruction_versions` in the existing AITS database. Writes require the current revision; concurrent edits return 409. The API only accepts the four text fields, with 6,000 characters per field. Versions record the editor and timestamp.

n8n uses its existing ingest credential to POST `{ "instructionsRead": true }` to the shared Content Studio ingest endpoint. This authenticated branch only reads the latest instructions. The workflow reads one snapshot per run and carries its revision in run state. Loading failure stops the run rather than silently ignoring saved instructions. Revision zero preserves the original prompt behavior; saved preferences supplement and supersede default editorial examples only.

Output schemas, verification code, schedules, models, official logo, brand colors/fonts, the four contact-banner details, and publishing approval remain outside the editable settings. Preferences cannot modify node configuration, access credentials, or enable publishing. Model instructions reinforce these restrictions; existing strict schema validation and the separate review/publishing API remain in force. Marketing still reviews generated text and images before posting.

Deployment: apply `backend/migrations/content-studio-instructions.sql` to `aits-db`, deploy the Workspace Worker, and apply `scripts/patch-content-studio-instructions.mjs` to a freshly downloaded shared Worker bundle while retaining all bindings. The patch fails if its single anchor changes. Publish the matching n8n version after verifying its authenticated read node. No social publishing test is required.

## One-time ideas

The library's **Generate from an idea** box accepts a 10–4,000 character topic and an educational or marketing style. It researches and prepares one additional review draft with the existing caption, article, image and contact-banner pipeline. It reads the current AI Instructions without editing them. Ideas do not occupy Monday/Thursday slots. Unsupported ideas return no draft rather than an unrelated fallback.

Authenticated `POST /api/admin/content-studio/ideas` accepts only `prompt`, `style`, and a client-generated 32-hex `requestId`. The existing Workspace gateway enforces access. The shared Worker stores the idea and requesting user in `content_studio_runs` under a `manual_idea_` ID before triggering the existing n8n webhook. n8n retrieves the stored idea through the authenticated, single-claim ingest check; webhook callers cannot supply replacement instructions. Repeating a request ID cannot generate another draft or overwrite an idea. One active request per user is allowed within 30 minutes. Polling resumes after a same-tab refresh and marks terminal jobs complete. Duplicate scheduled research throttling excludes idea requests.

Draft IDs use `ideaedu_` or `ideamarketing_` plus the request ID; they appear in All Drafts and the chosen style filter with a One-time idea label. The UI never calls publishing endpoints during generation. Late results remain review drafts even if the browser is closed. Staff must inspect generated claims, captions and images before choosing a publishing channel.

Deploy `scripts/patch-content-studio-ideas.mjs` against a fresh shared Worker download (already containing the AI Instructions read endpoint), preserve bindings, and apply the seven node transformations from `scripts/content-studio-idea-workflow.mjs` to the existing workflow. Explicit ideas may revisit an older topic; source verification still applies, and scheduled deduplication is unchanged. No new database migration or credential is needed. The patch deliberately rejects changed anchors for review. Use `STUDIO_IDEA_WORKFLOW` and `STUDIO_TEST_BUNDLE` when running `backend/tests/content-studio-ideas.test.mjs` for integration checks against the downloaded workflow and patched bundle.
